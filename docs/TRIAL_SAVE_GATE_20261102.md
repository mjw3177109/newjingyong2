# 原创试玩：存档战斗入口门禁补强（2026-11-02）

## 问题与最小修复

原有 `interact()` 已要求先向竹隐老人接取「竹影试炼」，但 `parseSave()` 的战斗位置校验仅检查试炼者未被击败、玩家在相邻格，**没有检查任务是否已接取**。因此手工编辑的 v2 JSON 可以在 `quest=unstarted` 时携带 `combat`，绕过新加的试玩入口门禁。

本次仅收紧**导入/本机读取的战斗检查点**：首次试炼的 `combat` 必须满足 `quest=active`、试炼者尚未击败、玩家与试炼者相邻。已完成任务的再试仍要求 `quest=completed`、胜利旗标及竹隐老人相邻；不改战斗规则、存档版本、奖励或交互逻辑。

兼容性边界：历史 v1/v2 **非战斗**存档保持原校验规则，尤其不因早期允许先挑战的版本留下的旗标而被拒绝；本次仅拒绝当前游戏流程无法合法产生的未接任务战斗检查点。

## 验证

- `tests/trial-entry.test.mjs`：拒绝未接任务的伪造战斗存档；接受已接任务的合法战斗存档；兼容旧版非战斗旗标。
- `tests/engine.test.mjs`：将三个先前使用不合法「未接任务战斗」合成样例的测试改为已接任务，保留原有位置、回血和低气血验证。
- 执行 `npm run check` 和 GitHub Actions 浏览器/审计作业；线上结果以对应提交的 Actions 为准。

此变更仅属于**原创 HTML5 试玩安全与状态一致性**，不是从 `jin.swf` 恢复的剧情。原始 SWF 已语义核实剧情事件仍为 **0**，FFDec 间歇性导出漂移仍需独立调查。
