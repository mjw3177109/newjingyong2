# 原创试玩银两上限与任务奖励一致性（2026-11-01）

## 问题
`parseSave` 接受银两 0–1,000,000,000 的有效原创试玩存档，但任务完成时无条件发放 30 两。若合法存档接近上限（如 999,999,995），完成任务会产生 1,000,000,025 两，导致刚完成的进度无法再通过存档解析器。这个缺口属于原创试玩状态一致性，不涉及原始 `jin.swf` 数值。

## 最小修复
- 在 `src/engine.js` 集中声明 `MAX_SILVER=1_000_000_000`，供存档解析和任务奖励共用。
- 任务完成时仅发放剩余额度内的银两（`min(30, MAX_SILVER-currentSilver)`），始终保留任务完成状态与唯一原创竹纹短剑。
- 日志记录**实际发放额**，而不是在接近上限时误报 30 两。
- `tests/engine.test.mjs` 新增 2 组上限边界情形（余额 999,999,995 和 1,000,000,000），验证任务奖励、道具唯一性及存档往返一致性。

## 验收
运行 `npm run check`；GitHub Actions 的 `html5-tests` 和真实 Chromium `browser-smoke` 为最终线上验证。既有普通余额的任务奖励仍为 30 两。

**边界**：这是 HTML5 原创演示经济系统修复；未核实任何原作剧情事件、原作银两上限或战斗数值。原作语义已核实事件仍为 0 条，PR 继续 Draft，不合并 `main`。
