# 原创试玩：试炼接取条件校验（2026-11-02）

## 发现的问题

在此前的 HTML5 原创试玩中，玩家可以在尚未拜访竹隐老人、未接受「竹影试炼」时直接与蒙面试炼者开战，提前将 `banditBeaten` 置为 true。任务导航要求先接任务，实际战斗入口却没有校验该条件，两者不一致。

## 最小修改

- `src/engine.js`：在与试炼者交互时，如果任务为 `unstarted`，只显示前往竹隐老人的提示并写入纪事，不开启战斗、不改变任务或奖励；`active` 阶段仍可正常挑战。
- `tests/trial-entry.test.mjs`：新增未接任务、重复交互、已接任务可战斗并撤退的 3 项测试。
- 更新 3 个旧测试文件：此前直接构造未接任务状态以测试战斗，现在明确设为 `active`，避免把历史演示漏洞当成预期规则。
- 存档 v2 结构不变；旧版已完成或已有战斗存档仍按既有解析规则兼容。未修改 SWF、FFDec、原创美术或其他仓库。

## 验证范围与证据边界

`npm test` 与 GitHub Actions 运行结果应以对应提交的实际日志为准；不能仅凭代码修改宣称通过。

**这是原创 HTML5 演示任务的逻辑修复，不是从 `jin.swf` 核实的剧情触发条件。** 目前已语义核实的原作剧情事件仍为 0。后续需在隔离环境中将 12 个优先 IF 的 AVM1 字节码、FFDec 导出及运行行为逐条对照，方可登记真实事件。
