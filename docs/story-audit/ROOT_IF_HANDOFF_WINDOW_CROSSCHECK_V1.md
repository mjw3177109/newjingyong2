# 原始 SWF 根时间轴 IF：私有审查交接与操作码窗口交叉校验 V1

## 本轮发现

现有 `swf_root_if_audit_handoff.json` 和 `swf_root_if_opcode_windows.json` 分别生成，但缺少一个独立的、按 `review_id` 逐条检查同一 SWF 指纹、根帧、DoAction 序号与 IF 字节偏移的交接门禁。单独成功生成两个文件并不等于它们仍指向同一批 IF。

## 最小实现

新增 `tools/crosscheck_root_if_handoff.py`。从两份**不含原始脚本和操作数**的 JSON 中核对：SWF SHA-256、实际候选集合、逐条坐标、结构性未核实状态，以及窗口内有限的比较操作码/语法前驱计数。任何身份、数量或坐标不一致均失败，且不写出已核实事件。

CI 在原始 SWF 结构清点任务中运行并上传 `swf-root-if-handoff-window-crosscheck` 脱敏 Artifact。测试位于 `tests/test_crosscheck_root_if_handoff.py`，覆盖合法对齐、跨 SWF、坐标篡改、候选身份/重复、语义断言以及操作码计数异常。

## 证据边界与下一步

校验成功只能说明**结构性定位对齐**，不能还原 IF 条件表达式、确认运行时执行路径、推断剧情、地图、道具、战斗数值或授予改编权。`verified_story_events` 和 `ready_for_html5_mapping` 均固定为 **0**。后续须在有权的隔离环境中逐条审查原始 AVM1 字节码、FFDec 脚本与实际运行行为，并经独立核验后才可更新正式剧情事件对照表。

## 2026-11-01：跨文件身份绑定补强

发现交叉核验器原先只核对两份 JSON 的匿名 ID 与根帧/DoAction/IF 偏移，却没有独立复算 `review_id = SHA-256(SWF_SHA256:action_tag_ordinal:action_sha256:if_source_offset)[:24]`。如果交接文件的 `action_sha256` 被更换而匿名 ID 和坐标保持不变，旧交接证据可能错误关联到另一份 Action 字节码。

现于交叉核验时复算该 ID，并要求 Action SHA-256 为合法 64 位十六进制；同时拒绝“直线前驱操作码数量超过声明窗口宽度”的输入。增加合成测试，覆盖 Action 指纹篡改、双方匿名 ID 同时伪造、错误指纹格式与窗口越界。该变更只加强**审计数据完整性**，不读取操作数、脚本、媒体，不代表剧情语义或改编权已经验证；已核实原作剧情事件仍为 **0**。

## 2026-11-02：空白私有审查清单完整性门禁

发现交叉核验器此前只检查**已出现**的 checkbox 值，缺少必需字段（甚至整个空字典）时仍可通过交叉核验；额外未定义字段也未被拒绝。这样可能让残缺/扩展的私有审查数据被误读为有效的未核实交接记录。

现在要求 checks 的字段集合与 build_root_if_audit_handoff.py 生成的七个字段**完全一致**：ffdec_script_sha256 必须为 JSON null，六个确认标志必须严格为 JSON false（拒绝数字 0、缺失字段及额外字段）。新增合成回归测试覆盖缺少运行时确认、缺少脚本哈希、额外字段和非布尔 0。只更改审计门禁，不改变原 SWF、HTML5 玩法、候选排序或现有报告 schema。

本修复只验证结构性审计交接清单的**完整性**，不提供原作剧情语义证据；已核实剧情事件仍为 **0**。真实 jin.swf 的 12 个 IF 交接目标是否全部通过，须以本次提交后的 GitHub Actions swf-inventory 结果为准。

## 2026-11-02：操作码窗口内部一致性检查

发现交叉核验器此前只验证直线前驱的类别列表长度及一个语法前驱计数。若脱敏窗口 JSON 的 `preceding_opcode_classes`、`comparison_opcode_count`、字节偏移或边界标志被意外改写，仍可能产生误导性的“存在比较操作码”结构提示。

现在对两组前驱偏移/类别做严格的长度、允许类别、偏移单调性和窗口宽度校验；直线前驱必须是完整前驱列表的后缀；比较操作码数量、边界截断标志和分支/不透明控制标志必须与类别列表一致。拒绝伪造类别、错序/越界偏移及不一致汇总。合成测试同时覆盖有效的边界截断情况。

**边界**：这只是两份脱敏报告的自洽性检查，并非重新解码 AVM1 字节码；上游原始 SWF 索引仍须独立运行。通过不等于运行时可达、IF 条件已还原、原作剧情事件已核实或拥有改编权。已核实原作剧情事件仍为 **0**。

## 2026-11-02：CLI 与导入调用的校验逻辑分叉修复

检查发现 `tools/crosscheck_root_if_handoff.py` 中意外存在两份同名 `_count`、`crosscheck`、`main` 及两处 `__main__` 入口。Python 直接执行脚本时，先调用**旧版宽松校验器**，随后才定义新版严格校验器；而单元测试通过 import 调用的是后定义的严格版本。结果是测试成功并不能证明 CI 的实际命令行交叉核验启用了操作码窗口内部一致性检查。

本次删除前一份重复定义，保留调用 `_checked_window` 的严格版本及唯一 CLI 入口。新增两项真实子进程回归测试：对篡改的 `preceding_record_count`，导入调用与 CLI 均必须拒绝且不能写出报告；合法窗口的 CLI 输出必须与导入调用完全一致。

修复只影响脱敏结构审计工具，不修改 `jin.swf`、FFDec、原始脚本、HTML5 游戏逻辑或事件对照表。**已语义核实原作剧情事件仍为 0**；通过此门禁只证明输入窗口自洽，不证明剧情条件、地图归属、运行时行为或发布权利。
