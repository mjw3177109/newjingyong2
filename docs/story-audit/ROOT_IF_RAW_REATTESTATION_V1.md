# 根时间轴 IF 原始 SWF 再核验门禁 V1（2026-11-02）

## 本轮发现的问题

此前 `tools/crosscheck_root_if_handoff.py` 会验证交接表与无操作数窗口的身份、坐标和内部一致性，但**不会重新读取 `jin.swf`**。例如，将 `comparison` 操作码类别同时改成 `boolean_logic`，再同步修改汇总计数和安全后缀，旧校验仍可能通过。两份来源一致的报告并不等于与原始字节码一致。

这属于审计证据完整性风险，不是游戏战斗逻辑漏洞，更不能当作已恢复原作剧情。

## 最小实现

- 新增 `verify_raw_evidence(swf_path, packets, handoff, windows)`：用原始 SWF 和原始审核包重新运行现有 `build_windows`、`build_handoff`，要求输出与待交接 JSON **完整相等**，包括窗口类别、顺序、写入提示、停止原因、身份和空白审核清单。
- CLI 新增成对参数 `--swf`、`--packets`。缺少其中一个即报错；兼容旧调用时仅执行原来的内部一致性检查。
- GitHub Actions 的 `swf-inventory` 作业现在明确传入 `jin.swf` 与 `reports/swf_root_if_review_packets.json`，在输出或上传交叉审计报告前执行原始字节码再核验。
- 新增合成 FWS/AVM1 测试：原始报告可通过；内部一致但与原始 SWF 不符的操作码重标记、交接元数据篡改必须被拒绝；CLI 失败不得生成报告。

仅重新读取原始文件，**不上传原始 SWF、解编译脚本、操作数、人物、图片或音频**；不改变 HTML5 玩法和存档格式。

## 验证范围与局限

这是一项从原始字节码到脱敏报告的确定性复核，能识别报告生成后被修改或报告与当前原始 SWF 不一致的情况。它**不是**独立的 AVM1 解释器或运行时轨迹，也不证明 IF 表达式含义、剧情触发、地图归属、战斗数值或发行授权。

新测试与真实 `jin.swf` CI 的实际结果以本提交后 GitHub Actions 为准。当前已语义核实原作剧情事件仍为 **0**，`ready_for_html5_mapping=0`，PR 继续 Draft，`main` 不变。

## 下一阶段

在私有、合法授权的隔离环境中对优先 12 个 IF 的操作数、FFDec 脚本和运行时状态做交叉验证；只在独立核实后写入剧情/事件对照表。FFDec 偶发导出漂移仍需单独排查，原始 SWF 再核验不能修复 FFDec 不确定性。
