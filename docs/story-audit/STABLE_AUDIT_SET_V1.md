# 双导出稳定候选审计清单 V1（2026-10-30）

## 问题与目标

FFDec 在同一 Java 8 CI 环境中对相同 jin.swf 的两次导出出现过 474/3 与 469/2 的跳转/守卫计数差异。旧的前 100 候选列表不能被直接视为稳定证据。新工具 tools/build_stable_audit_set.py 只保留两次导出均选中、脚本内容哈希相同、跳转和守卫计数一致的候选，排除任何不一致者，并输出不含原始脚本或原始路径的审计清单。

## 输出规则

- 两次输入的 SWF SHA-256 必须相同，且匿名索引、候选 ID、跳转总数均经过验证；不一致直接失败。
- 同一匿名路径若只在一份候选列表中出现，排除原因 selected_in_one_export_only。
- 若两份脚本内容哈希不同，排除原因 script_content_changed。
- 若内容相同但跳转/守卫计数不同，排除原因 syntax_counts_changed。
- 其余候选标记 reproducible_syntax_unverified，输出路径哈希、内容哈希、候选 ID、语法计数；计算稳定集合指纹便于跨运行对比。
- 仅在同一次 CI 的两份独立导出中确认语法一致，不能证明跨运行稳定，更不能证明原作剧情、地图、NPC、战斗数值或事件条件已经核实。已核实原作剧情事件数固定为 0。

## 测试与后续

新增 6 项合成测试：相同导出、内容漂移、候选集合漂移、语法漂移、篡改拒绝、顺序无关。GitHub Actions 产生 ffdec-source-free-stable-audit-set Artifact，不公开 FFDec 源码、图片或音频。后续比较不同 CI 运行的 stable_manifest_sha256，排除跨运行漂移后，在隔离环境审查脚本上下文，逐条建立有来源的事件触发条件和结果；目前不能把任何候选当作原作剧情事件。
