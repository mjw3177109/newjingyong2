## 后续逐事件登记格式

每条原作事件仅在**真实脚本证据**存在后登记：
- `source_event_id`：文件哈希 + SWF 时间轴/脚本定位 + 本地稳定编号
- `source_evidence`：FFDec 导出路径、行号或字节码偏移、脚本 SHA-256（不公开脚本全文）
- `trigger`：原作确认的地图/人物/任务旗标条件
- `effects`：已确认的变量变化、道具、战斗、传送、对话摘要
- `html5_event_id`：对应实现及自动化测试名称
- `confidence`：已证实 / 部分证实 / 未证实
- `rights_status`：原作剧情改编和发布授权确认情况

不得将未经核实的故事记忆或网络攻略当作已解析的 SWF 证据。

## 2026-10-31 原创试玩移动与玩家气血上限一致性

- 发现纯 JS 引擎的 `move(state, dx, dy)` 原本仅依赖 UI 传入合法方向，直接调用时允许斜走、一次移动多格或非有限数字，可能绕过地图碰撞并生成无法读取的存档。
- 现只允许每次恰好移动一个正交格，拒绝对角、跨格、小数、非有限数字和零位移；原有键盘与触屏的四方向操作保持不变。
- 发现存档解析器允许修改玩家 `maxHp` 为 1–100，但演示玩法从不改变最大气血，UI 也固定显示 100。现在拒绝非 100 的伪造上限，合法低气血存档仍可读取。
- 增加 2 项 Node 回归测试。**这属于原创 HTML5 试玩修复，不是原始 SWF 的移动规则或气血数值证据**；已语义核实原作事件仍为 **0**。
